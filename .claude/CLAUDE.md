## Project context
- **Goal:** the user enters a stock ticker + forecast horizon; the app fetches price history, estimates parameters, runs a GBM Monte Carlo simulation, and shows simulated paths + risk stats.
- **Architecture:** monorepo.
  - `backend/` = Python (core library, CLI, FastAPI).
  - `frontend/` = Next.js + TypeScript + Tailwind, deployed on Vercel.
- **Phases:** 1 core library, 2 CLI, 3 FastAPI, 4 Next.js frontend, 5 deploy, 6 README, 7 extras. Phases 1-6 are done; 7a (risk-free drift option) and 7b (backtesting) are done; rest of 7 next.
- **Live:** website https://monte-carlo-stock-sim.vercel.app, API https://monte-carlo-stock-api.vercel.app (docs at `/docs`).
- **Defaults:** 2-year lookback, 10,000 simulations, 252 trading days/year, fixed seed 42, historical drift by default (risk-free drift optional), US and Indian (`.NS` / `.BO`) tickers.
- **Drift models:** `drift="historical"` (default) uses mu estimated from log returns; `drift="risk_free"` sets mu = r (risk-neutral GBM), sigma still from history, and the historical mu is still returned (`parameters.mu` = drift used, `parameters.mu_historical`; `settings.risk_free_rate` / `settings.rate_source`, both null for historical). Rate order: user override (decimal, -0.05..0.25) > live `^IRX` for USD (`core/data.py` `fetch_live_tbill_rate`, 3 s timeout, None on failure) > `core/rates.py` defaults (USD 3.70%, INR 5.35%, generic 4.00%, "as of" note in the file; update there). Sources: "user override", "live ^IRX", "default for USD/INR", "generic default". A rate without `risk_free` drift is rejected (API 422, CLI error).
- **Backtesting** (`core/backtest.py`, separate from the simulator): history fetched once with `core/data.py` `fetch_price_history(ticker, start, end=None)` (date range; ~10y for rolling, lookback-before-start for single). No look-ahead: for start t (last close on or before the requested date) mu/sigma come only from closes in `[t - lookback, t]` (calendar offset, 7-day tolerance for a "full" lookback, >= 60 closes). `single_backtest(ticker, start_date, horizon, lookback, drift, n_sims=10000, seed, risk_free_rate)` = usual analysis + `backtest` {start/end/lookback_start/latest_start dates, `actual_path`, `actual_final`, `actual_return_pct`, `percentile_rank` 0-100, `inside_50`, `inside_90`}. `rolling_backtest(..., n_windows<=40 (min 5 available), n_sims=2000)` = evenly spaced start indices with full lookback + horizon, vectorised (cumsum moments + exact one-step GBM finals; ~7 ms compute), `summary` {coverage_50/90, below_p5, above_p95, mean_percentile_rank, 10-bin `pit_histogram`} + `windows`. Risk-free in backtests uses today's per-currency default or the override (never live ^IRX) and sets `settings.rate_note`. `_from_prices` variants take PriceData (tests, mocks). Errors: `BacktestDateError` (future / too recent, message names the latest valid date) -> API `invalid_input`; not enough history -> `insufficient_data`.
- **Design (60/30/10 colour rule):**
  - 60% Forest Green `#1F3D2B` — main background.
  - 30% Sand Beige `#E8DCC4` — cards, text, secondary surfaces.
  - 10% Electric Purple `#8B5CF6` — accent only: primary button, mean path, key numbers.

## How to run
- Setup (from `backend/`): `python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements-dev.txt`
  - `requirements.txt` = what the deployed API needs (numpy, pandas, yfinance, fastapi, uvicorn).
  - `requirements-dev.txt` = `-r requirements.txt` + rich, matplotlib (CLI) and pytest, httpx (tests).
- API (from `backend/`): `uvicorn api.main:app --reload`, then open http://127.0.0.1:8000/docs
  - `GET /` -> service name, description and links (`/docs`, `/api/health`, website).
  - `GET /api/health` -> `{"status": "ok"}`
  - `POST /api/simulate` body: `ticker`, `horizon` (required, max 5y), `lookback` (`6mo|1y|2y|5y`, default `2y`), `n_sims` (1000-20000, default 10000), `seed` (default 42), `drift` (`historical|risk_free`, default `historical`), `risk_free_rate` (optional decimal -0.05..0.25, only with `risk_free`). Cache key includes drift and rate.
  - `POST /api/backtest` body: `mode` (`single|rolling`, required), `ticker`, `horizon`, `lookback`, `seed`, `drift`, `risk_free_rate` as above, `start_date` (YYYY-MM-DD, required for single, rejected for rolling, not in the future), `n_sims` (default 10000 single / 2000 rolling), `n_windows` (rolling only, 5-40, default 40). Single is trimmed like simulate (`serialize_backtest` also downsamples `actual_path` onto `days`); rolling passes through (<= 40 windows, ~12 KB). Cached in the same TTL cache under a `("backtest", ...)` key.
  - Errors are always `{"error": {"code", "message"}}`: `invalid_ticker` 404, `insufficient_data` 422, `invalid_input` 422, `data_unavailable` 502, `internal_error` 500.
  - Env vars: `ALLOWED_ORIGINS` (comma-separated, default `http://localhost:3000`), `CACHE_TTL_SECONDS` (default 900, 0 disables), `CACHE_MAX_ENTRIES` (default 100).
- CLI (from `backend/`): `python cli.py --ticker AAPL --horizon 6m`
  - Options: `--lookback 2y`, `--sims 10000`, `--seed 42`, `--save DIR` (default `./output`), `--no-show` (save charts without opening windows), `--json FILE` (write the full `run_simulation` result), `--drift {historical,risk_free}`, `--rate FLOAT` (decimal, only with `--drift risk_free`), `--backtest DATE|rolling`, `--windows N` (rolling, 5-40, default 40). `--sims` defaults to 10000 (2000 for `--backtest rolling`).
  - Backtest charts: `<TICKER>_<horizon>_backtest_<start>.png` (fan + actual path) and `<TICKER>_<horizon>_calibration.png` (PIT histogram, dashed ideal line).
  - Charts are saved as `<TICKER>_<horizon>_paths.png` and `<TICKER>_<horizon>_hist.png`.
- Tests (from `backend/`): `python -m pytest` (no network; yfinance and `run_simulation` are mocked; an autouse fixture in `tests/conftest.py` makes the live `^IRX` lookup return None).
- Frontend (from `frontend/`, Node 22+): `npm install`, then `cp .env.example .env.local` (sets `BACKEND_URL=http://localhost:8000`), then `npm run dev` and open http://localhost:3000
  - Run both together locally: terminal 1 `cd backend && source .venv/bin/activate && uvicorn api.main:app --reload` (port 8000); terminal 2 `cd frontend && npm run dev` (port 3000). The browser calls the relative `/api/simulate`; `next.config.ts` rewrites `/api/*` to `BACKEND_URL` only when it is a valid http(s) URL (validated by `lib/backend-url.ts`; read at build time). Do not add Next.js API routes under `/api`.
  - Demo mode (no backend / no Yahoo access): `NEXT_PUBLIC_DEMO_MODE=true npm run dev` serves `mocks/sample-response.json` (or `mocks/sample-response-risk-free.json` when drift is risk-free; a rate override is not reflected in demo data); Backtest mode serves `mocks/sample-backtest-single.json` / `mocks/sample-backtest-rolling.json` (any ticker/date). Regenerate all four with `npm run generate:mock` (needs the backend venv active; uses `core.simulate_from_prices` / the backtest `_from_prices` functions + `api.serialize` on synthetic prices, live rate disabled; the backtest history uses fat-tailed vol regimes, seed picked so the demo shows typical under-coverage).
  - Checks: `npm run lint`, `npm test` (Vitest: formatting helpers, error-code mapping, chart data, drift/rate parsing + URL params, backtest dates/URL params/calibration + mock shape), `npm run build`.
  - Layout: `app/` (layout with site metadata + Open Graph/Twitter tags, page, globals.css with the palette tokens, `opengraph-image.tsx` generated share card), `components/` (Simulate | Backtest switch at the top of InputCard; Simulator keeps one result per mode; BacktestResults = single (result card with hit/loss band badges, FanChart with `actual` overlay as a solid sand line) and rolling (coverage cards, CalibrationChart with dashed ideal line, windows table, explainer); BackgroundGlow = fixed page-wide glow that follows the cursor and drifts, paused when hidden, static with reduced motion; Simulator = state + URL sync, InputCard, Results, FanChart, HistogramChart, States, HowItWorks), `lib/` (`types.ts` mirrors the API response, `api.ts` fetch + demo mode, `errors.ts` code -> friendly copy, `format.ts` Intl money/percent/date (`formatMoneyRange`: both ends 2 decimals below 1,000 by the larger end, whole numbers at/above), `chart.ts` Recharts data + nice axis ticks + reference-label layout, `options.ts` tickers/horizons/defaults, `drift.ts` drift options + rate % parsing + `drift`/`rate` URL params (omitted for historical so default URLs are unchanged), `backtest.ts` modes, start-date max (today - horizon in calendar days - 5) / default (max - 14 days), `mode=backtest`/`test=rolling`/`start=` URL params (omitted for Simulate; the effective start date is written), coverage verdicts (`assessCoverage(coverage, p, n)`: within 2 binomial SEs sqrt(p(1-p)/n) = "Within sampling noise", else "Bands too narrow" / "Bands too wide"; badge tooltip + caption note that overlapping windows make true uncertainty larger), `site.ts` site URL/name/description).
  - Downside figures (probability of loss, VaR, negative changes, backtest misses) use terracotta `#E07A5F`; backtest "inside the band" badges use the sage `hit` token `#9CCB9F`; purple text uses the lighter tint `#B39DFB` for contrast.
- Code layout: `core/` = maths (do not change for UI work; `rates.py` = risk-free rate defaults + resolution), `cli.py` = terminal UI on `core.run_simulation`, `plots.py` = matplotlib charts.
  - `api/` = FastAPI: `main.py` (app, routes, error handlers, CORS), `schemas.py` (Pydantic models + validation), `serialize.py` (downsamples to <= 200 points + `days` axis, 50 sample paths; `serialize_backtest`), `cache.py` (in-memory TTL cache of trimmed results).

## Deployment
- Full click-by-click steps: `DEPLOY.md` (repo root). Two Vercel projects from this repo:
  - **API**: Root Directory `backend`, FastAPI preset. Entrypoint `backend/index.py` (re-exports `api.main:app`; keep it a one-line import). Python pinned by `backend/.python-version` (3.12). Vercel installs only the runtime deps (`requirements.txt`, mirrored in `pyproject.toml` `[project].dependencies`; `tests/test_deploy.py` keeps them in sync). `backend/.vercelignore` drops tests, CLI, plots, dev requirements, output and caches. Installed deps are ~180 MB unzipped / ~55 MB zipped.
  - **Website**: Root Directory `frontend`, Next.js preset, env var `BACKEND_URL` = the API's production URL (e.g. `https://<api>.vercel.app`). It is read at build time, so redeploy after changing it. Missing/invalid -> build still succeeds with a warning, no rewrite, and the UI shows "data unavailable" (production builds map non-JSON `/api` responses to `data_unavailable`).
  - `ALLOWED_ORIGINS` is not needed when the website proxies through the rewrite (the browser only talks to the website's own domain); set it only if a browser calls the API URL directly.
  - `NEXT_PUBLIC_DEMO_MODE` is off unless exactly `true`; never set it on the production website.
- Fallback if Yahoo blocks Vercel's IPs (every ticker returns `data_unavailable`): Render Blueprint `backend/render.yaml` (free plan, `pip install -r requirements.txt`, `uvicorn api.main:app --host 0.0.0.0 --port $PORT`, health check `/api/health`), then point `BACKEND_URL` at the Render URL and redeploy the website.
- Pushing to `main` redeploys both projects to production; other branches get preview deployments.
